# Natural compact — decided and open (2026-11-05)

A status note over `requirements.md`, `brainstorm.md`, `taskFindings.md` and `specs/`. It does not
change the requirements; it separates what is settled from what still blocks a build.

## Decided

- **Continuation happens in the same session**, not in a new one. A custom compaction
  (`session_before_compact` returning `{ summary, firstKeptEntryId, … }`) rewrites the projection;
  omitted entries stay in the session file. The fresh-session destination is deferred, not
  rejected (`taskFindings.md` → "Destination decision").
- **Interactive TUI first.** RPC/print modes do not apply a handoff in v1; automated approval
  transport is future work.
- **Thresholds are 50% (quiet opportunity) and 60% (active ask)**, and both require a verified
  natural boundary — a safe pause or a coherent milestone counts, active tool runs never do.
- **Boundary judgment goes through decision-server → Jev → the human.** A generic `{}` is not a
  verified boundary; uncertainty escalates.
- **The human approves.** The reason, work type, handoff text and cut point are shown; edit and
  decline are first-class; approval binds the handoff text, the session file, the branch head and
  `firstKeptEntryId`. The editor's draft is never part of the binding.
- **Handoff generation is lazy and read-only**, on a provider configured once (prefer an available
  OpenCode Go Flash model), with bounded input and structured output that maps to `details`.
- **Logging is local, restricted, 30-day default retention**, and includes the handoff text and the
  before/after measurements. Unavailable is distinguished from zero.
- **Failure offers ordinary Pi compaction as a visibly separate option**, never silently.
- **`details.readFiles` / `modifiedFiles` must round-trip**; a custom summary without them loses
  Pi's file tracking.

## Open (Gate 0, blocking)

- **In-place end to end proof**: call `compact()` with our summary in a real TUI and record what
  the next turn contains, that no turn ran, that the draft/caret survived, that reload works, and
  that `/tree` can return to the pre-cut span.
- **Compaction-contract limits**: whether an extension-initiated compaction's `details` survive
  repeated compaction, and what Pi's own threshold compaction does to our summary (pass through,
  intercept, or regenerate).
- **The decision-server boundary contract**: a typed `verified` / `not_boundary` / `uncertain`
  answer, who owns the adapter change outside this repo, and its cost.
- **What "recoverable" means** for a human who regrets a handoff — tree navigation or editing the
  file. If it is "only by editing", the UI and acceptance criteria must say so.

## Open (design defaults)

- Cooldown after a decline (proposed 15 minutes) and whether it is wall clock, boundary count, or
  both.
- Default cut point ("keep the last N turns" vs "keep none") and its wording.
- Which threshold-compaction policy to adopt for compactions the extension did not start.
- Log-write failure: block by default with an explicit "continue without the audit record" path.
- Default handoff model when no Flash model is available.

## Already true in the repository

- `extensions/shared/jev.ts` exposes `runJevDecision` and `askJev`; the Pi adapter accepts a
  `stop` event with `reentry`, and `transcriptPath` now points at a Claude-shaped session mirror
  (`extensions/shared/jev-transcript.ts`), so Jev-side decisions can read Pi turns and usage tokens.
- `extensions/shared/full-screen.ts` and the BTW overlay pattern give a reviewed full-window or
  docked surface without stealing the editor.
- `docs/explainer/natural-compact-loop.html` and `natural-compact-agent.html` are the visual
  explainers of the flow.
