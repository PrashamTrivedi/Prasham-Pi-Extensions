# Changelog

## Unreleased

- **sandbox-dev prompts only what is risky.** The permission floor stops confirming reads outside the working directory (only the protected-path denies restrict them) and stops confirming writes under `~/.pi/agent`, `/tmp`, and anything in `PI_SANDBOX_ALLOW_ROOTS`. `bash.confirm` keeps only destructive or shared-state commands — `sudo`, `rm -rf`, `rm -r`, `git reset --hard`, `git push`, `chmod`, `chown`, publishes — so installs and network calls are judged contextually by the Jev shell-safety pass-2 instead of prompting blindly. Patterns match on token boundaries now, so `git pushy` and `curly` no longer match while `git push` and `curl` do, and `rm -r` no longer matches inside `rm -rf`. `/dev-status` reports `policy: N confirm(s), M auto-approved (Jev)` per session, the before/after instrument for the tier.
- **The decision server is the only judge of a tool call.** `sandbox-dev` no longer holds a permission policy: there is no allow/confirm/deny classification, no dangerous-command list, no protected-path list, no allow-root environment variable (`PI_SANDBOX_ALLOW_ROOTS`, added in the previous change, is gone), and no shell-approval handshake. Every `tool_call` - shell, read, write, edit, mcp, subagent, fetch - is mapped to the neutral jev-harness shape and sent to the decision server. An approval runs the call silently; a reject, an "ask", or an unreachable server becomes exactly one plain yes/no prompt, and with no UI the call is blocked. Nothing is remembered between calls. `jev-gate` loses its `tool_call` handler and keeps its result and stop hooks, so one gate owns the call; the neutral mapping moved to `shared/tool-call.ts` because both extensions need it. The two `dev_*` gate tools are exempt, and commands the human types with `!cmd` are not judged.
- **Decision-server setup is documented.** [docs/decision-server.md](docs/decision-server.md) records the enabled decisions, the coverage map by tool kind, a judge-only probe recipe, the measured per-call cost, the contextual verdicts observed on this machine, the remaining gaps (reads, writes, and the missing `sudo`/force-push/`chmod` shell rules), and how to roll back the harness config.
- **Project context reports Git state.** Inside a repository the injected block now carries the branch, the first remote, and the uncommitted-file list (bounded by `PI_GIT_STATUS_MAX`, default 20 lines); outside a repository nothing is added. The tree stays cached per session, while Git state is re-read on every agent run so it is never stale.
- **New memory extension.** Each project gets a local Markdown memory mirroring Claude Code's layout (`~/.pi/agent/projects/<escaped-cwd>/memory/`): a `MEMORY.md` index plus `next_`, `project_`, `feedback_`, and `reference_` files with frontmatter and a closing **Why** / **How to apply**. Only the location and a short read/write protocol is injected, on every agent run, so the model reads and writes memories with its normal file tools and jev-harness `memory-hygiene` recognises the files. `PI_MEMORY_ROOT` overrides the base directory.
- **Fabric's UI is rebuilt around agents, not commands.** Delegated agents appear as one-line rows below the prompt the moment they spawn — each with a generated, stable color, model, live activity, status and elapsed time; main first, children indented, spawn batches marked as groups, capped at six rows. `/agents` is the single way in: a tree with expand/collapse that opens any agent (main included) as a full-window transcript with a hue-tinted header, rule and message bands, plus side-by-side columns for a spawn group and `s` to toggle them. An agent idle for ten minutes leaves the UI, replacing the old five-minute finished-run prune. The status line, `/team`, `/transcript` and `alt+t` are removed; tool result cards are unchanged.
- **Fabric shows the whole run, not a pane.** Each child now persists a real Pi session (`--session-dir .../sessions --session-id <agent-id>`) instead of running ephemeral. `Enter` in `/team`, `/transcript [id|prefix|label]`, or `alt+t` replay that transcript as a full-window custom screen (not an overlay) sized to Pi's interactive area: user/assistant text, thinking, tool calls, and tool results, with paging and a live refresh while the run still works. The run list includes pruned runs. The compact `◆ PI FABRIC` panel is gone; the accent status line is the only persistent surface (`/team hide` / `/team show` now toggle it). Finished runs leave the live list and `/team` view five minutes after `finishedAt`; pruning is display-only, so `agent_status`, result cards, and the saved transcript keep working, and `/team all` (or `a` in the inspector) lists them again.
- **MIT license.** Added `LICENSE`; `package.json` is `MIT`; the README states the credit and notice requirement.
- **Duck now mimics Claude Code's question flow.** The model returns a JSON array of questions (`header`, `question`, `options`, `allowOther`); the parser is tolerant (fences, prose, clamping to 4 questions and 4 options) and falls back to raw text. `/duck answer` opens a shared AskUserQuestion-style questionnaire and writes the answers into the editor for review; it never auto-sends and preserves an existing draft.
- **Cockpit and duck are docked, not floating.** Both moved from `ctx.ui.custom({ overlay: true })` to a `setWidget(..., { placement: "aboveEditor" })` panel that reserves layout space instead of covering the transcript. The cockpit collapses to one line below 60 columns, since widgets have no `visible(width)` gate.
- **Fabric: unrecorded models are unrestricted.** A model absent from the hierarchy may be spawned from any caller and may delegate to any model; ranks only order delegation among named models. A `/reload` now re-applies an edited hierarchy to the existing root, so a new session is no longer required.
- **Cloudflare AI usage is kept, not retired.** It renders only while a `cloudflare-workers-ai` model is active and clears otherwise, so it and `usage/` never compete for the status line.
- **One documentation guide per extension** under `docs/`, linked from the README.
- Native `sandbox-dev` port: `skills/sandbox-dev/SKILL.md`, the `prompts/codePlanner.md`, `prompts/startWork.md`, and `prompts/completeWork.md` templates, and the `extensions/sandbox-dev` extension.
- Minimal permission floor: allow/confirm/deny rules over `tool_call` and `user_bash`, fail-closed without UI, built in with no config file. Shell-safety pass 2 is deferred to `extensions/jev` and may only escalate.
- Conversational plan gate (`dev_request_approval`, `/dev-approve`): `dev_request_approval` reads the plan and appends the gate to the chat. The human's reply in the transcript is the record; the extension records no approval and does not classify or intercept the reply. `/dev-approve` is an explicit human command that anchors the outcome and starts `/startWork`.
- Single-outcome supervision with a turn budget (`dev_outcome_met`); supervision arms on the first source write, and budget exhaustion is tracked separately and is not reported as met.
- Unit and wiring tests for the permission floor, `strongest()` escalation, the conversational gate, and outcome supervision.

## 0.1.0

Initial Git-installable package under PrashamTrivedi/Prasham-Pi-Extensions.

- Fabric recursive delegation with configurable same-or-lower model ranks.
- Compact live widget, responsive comparison cards, and framed team inspector.
- Portable external configuration and explicit worker extension loading.
- Launch-baseline patch capture including non-ignored new files, without altering worker staging.
- Project and nested instruction context helpers.
- Opt-in configured Cloudflare usage estimates and optional billing lookup.
- Skill-name preview and explicitly confirmed corrections; no startup writes.
- Illustrative SVG/PNG and offline interactive HTML preview.
- Automated tests and CI. License selection pending.
